# OKX 보존 한계 실측 → 전방 기록 전환 (2026-08-20)

## 1. 실측 결과와 그 해석

| 데이터셋 | 5m | 1H | 1D | limit 해석 |
|---|---|---|---|---|
| open_interest_history | 8h (100행) | 4일 (100행) | 99일 (100행) | **무시, 100행 캡** |
| contract_taker_volume | 8h (100행) | 4일 (100행) | 99일 (100행) | **무시, 100행 캡** |
| taker_volume | 2일 (575행) | 30일 (720행) | 180일 (180행) | 무시, 보존창 통째 |
| long_short_ratio | 2일 (575행) | 30일 (720행) | 180일 (180행) | 무시, 보존창 통째 |
| liquidation_orders | — | — | — | **5시간 (1600건)** |

**중요한 구분**: 앞의 두 데이터셋이 모든 조합에서 *정확히 100행* 이라는 건
보존 한계가 아니라 **응답 크기 상한**이다. 8h / 4일 / 99일은 각각
"5m 100봉 / 1H 100봉 / 1D 100봉" 일 뿐이다. 진짜 깊이는 페이지네이션으로
과거로 넘겨봐야 나온다. `--retention` 을 2단계(단일 호출 + walkback)로 고쳤다.

다만 walkback 이 어디까지 가든 **결론은 바뀌지 않는다**. 같은 rubik 계열인
`taker_volume` 의 실측 보존이 5m 2일 / 1H 30일 / 1D 180일이고, 우리에게
필요한 건 2023-11 이후 약 1,000일이다. 격차가 두 자릿수 배다.

## 2. 판정

> **펀딩을 제외한 모든 OKX 파생 통계는 소급 백테스트에 쓸 수 없다.**
> OI·테이커·롱숏비·청산 프린트는 **지금부터 모으는 전방 기록**으로만 쓸 수 있다.

따라서:

- 청산 캐스케이드 탐지를 OI 로 교체하려던 계획은 **소급 검증 불가** → 보류.
- 청산 히트맵(가격/거래량 기반 추정)을 계속 쓰는 것 외에 대안이 없다.
- 대신 히트맵을 **실측으로 검증하는 길이 열렸다** (§4).

## 3. 전방 수집기 — `examples/collect_forward.py`

append-only + 타임스탬프 중복 제거. 재실행/재시작에 안전하고, 매 실행마다
커버리지와 **공백(gap)** 을 보고한다.

```
python examples/collect_forward.py            # 5m 통계 + 청산 프린트
python examples/collect_forward.py --status   # 현황만
```

실행 주기 = 보존 한계가 곧 마감 시한:

| 대상 | 최소 주기 | 놓치면 |
|---|---|---|
| 청산 프린트 | **4시간** | 영구 손실 (보존 5h) |
| 5m 통계 | **2일** | 영구 손실 (보존 2d) |
| 1H 통계 | 30일 | — |

`--status` 는 5m 40시간 초과, 청산 4시간 초과를 경고한다.
같은 ms 에 여러 청산이 찍히므로 ts 만으로 중복 제거하면 유실된다 —
`ts|posSide|bkPx|sz` 복합 키를 쓴다.

## 4. 히트맵 실측 검증 설계 — `examples/heatmap_validate.py`

청산 프린트는 `bkPx`(체결가)와 `sz`(수량)를 준다. **정답지가 존재한다.**
히트맵은 이 프로젝트에서 지금까지 한 번도 정답지와 대조된 적이 없다
(v2 과소멸 버그가 `liq_imbalance_hm` 을 '레인지 내 위치' 프록시로 만들어
놓고도 유효 신호처럼 보였던 것이 그 대가다).

시각 t 의 청산 각각에 대해 **t 이전 정보만으로** 만든 히트맵의 예측 밀도를
읽고, 세 대조군과 비교한다.

- `균등` — 정보 없음
- `근접도` — 현재가로부터의 거리만. **핵심 대조군.** 청산은 원래 현재가
  근처에서 많이 난다. 히트맵이 그걸 재서술하는 것뿐이면 여길 못 이긴다.
- `시간셔플` — 귀무분포

판정 기준:

```
Δlift(히트맵 − 근접도) > 0 이고 t > 2   ->  근접도 이상의 정보 있음
부분lift > 1.1                          ->  거리효과 층화 후에도 신호 잔존
둘 다 아니면 히트맵은 '현재가 근처' 를 다시 쓴 것에 불과하다.
```

방향 검정도 함께: 롱 청산(`posSide=long`)은 현재가 **아래**, 숏 청산은 **위**.

`--selftest` 로 합성 정답지 배관 점검. 채점 원시함수는
`tests/test_heatmap_validate.py` 로 고정 (특히 "예측이 근접도와 동일하면
층화 후 정보가 남지 않는다" — v2 가 빠졌던 함정을 테스트로 박아뒀다).
