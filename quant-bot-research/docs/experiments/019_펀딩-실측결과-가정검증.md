# 펀딩비 실측 결과 — 가정이 틀렸고, 좋은 쪽으로 틀렸다 (2026-08-20)

OKX 실측 2,820건 (10심볼 × 282정산, 2026-05-18 ~ 2026-08-20).

**결론: 펀딩은 사실상 비용이 아니다. 손익분기 대비 여유가 37~100배.
게다가 우리 북은 76% 숏이라 평균적으로 **받는다**. 지금까지의 '항상 지급' 가정은
과도하게 보수적이었다. 단, TRX 하나만 정반대다.**

## 손익분기 대비 — 논쟁 종료

| 셋업 | BE 펀딩 | 실측 \|평균\| | 여유 |
|---|---|---|---|
| fib lb3 상위1% TP2R | 13.69 | 0.137 | **+13.55** |
| fib lb2 상위1% TP3R | 10.97 | 0.137 | +10.83 |
| vol 상위1% TP2R | 9.36 | 0.137 | +9.22 |
| choch 상위1% TP2R | 7.16 | 0.137 | +7.02 |
| fib lb3 상위3% TP2R | 5.28 | 0.137 | +5.14 |

**펀딩은 이 셋업들의 판정에 아무 영향이 없다.** 이전 검증 표의
`순R@펀딩1bp`, `순R@펀딩3bp` 열은 전부 과도하게 비관적이었고,
실제 값은 **`순R@0` 열에 가깝거나 그보다 약간 나은 쪽**이다.

즉 확정 수치는:
- `fib lb3 / 상위1% / fib0.4 / TP2R / 연속` → **순R ≈ +0.113 (t=3.10)**
- `vol / 상위1% / TP2R / 연속` → **순R ≈ +0.088 (t=2.12)**

부호까지 반영하면(숏이 rate>0 에서 수취) 미세하게 **더 좋아진다**:
정산당 +0.137bps × 약 1.75회 / R≈170bps ≈ **+0.0014R** 의 순풍.

## TRX 는 반대다 — 제외 근거

TRX 만 평균 −1.138bps, 양수 32%, 최저 −12.9bps. **TRX 숏은 지급한다.**

TRX 의 1R 은 가장 작다(96.9bps). 숏 기준 정산당
`funding_R = rate_bps / risk_bps = −1.138 / 96.9 = −0.0117R`,
1.75회면 **−0.0205R**. 후보 셋업의 +0.088R 중 **23%를 펀딩만으로 잃는다.**

이건 우연이 아니다. TRX 는 이전 검증에서도 계속 최악이었다
(수수료 부담 0.14~0.18R, 4H 레벨 연구에서 유일한 일관 음수).
**변동폭이 작아 1R 이 작고, 그래서 모든 고정비용에 취약하다.**

→ **TRX 는 유니버스에서 제외한다.** 심볼 9개로 재집계 필요
(제외 시 t 가 오를 가능성이 높다).

## 아직 못 본 것 — 캐스케이드 조건부

`--cascade` 는 OHLCV 를 못 찾아 실행되지 않았다(폴더 분리 문제, v0.16.2 에서 자동 탐색 추가).
전체 평균이 +0.137bps 라도, **하필 캐스케이드 직후 8시간만 음수로 기울** 가능성은 남아 있다.
겹치는 구간이 2026-05-18 ~ 2026-07-05 (7주) 뿐이라 표본은 작지만 방향은 볼 수 있다.

다만 여유가 +5~13bps 인 상황에서 조건부가 이를 뒤집으려면 캐스케이드 직후 펀딩이
평시 대비 **40~100배** 로 악화돼야 한다. 현실적으로 불가능에 가깝다.
→ **펀딩은 사실상 종결. 조건부 확인은 형식적 절차.**

## 부수 수정 (v0.16.2)

1. **`examples/*.py` 전부에 sys.path 부트스트랩** — `python examples/x.py` 로 실행하면
   sys.path[0] 이 `examples/` 라 프로젝트 루트의 `qbot` 을 못 찾고, 예전에 설치했거나
   **다른 버전 폴더의 qbot** 이 잡힌다. v0.16.0 에서 `resolve`/`fetch_meta`
   AttributeError 가 난 원인이 이것이다. 이제 로컬 패키지가 항상 우선한다.
   (`from __future__` 다음에 삽입해야 한다 — 앞에 넣으면 SyntaxError)
2. **`okx_data` / `cache` 폴더 자동 탐색** — 현재 → 부모 → 형제 폴더 순.
   버전 폴더를 새로 풀어도 이전 폴더의 데이터를 찾아낸다.
3. **빈 결과 KeyError 방어** — `cascade_conditional` 이 분석 가능한 심볼을 못 찾으면
   이유를 심볼별로 출력하고 빈 프레임을 반환한다.
4. `fetch_meta` 조회를 데이터셋 키로 정확히 (이전엔 마지막 항목을 임의로 집었다).
