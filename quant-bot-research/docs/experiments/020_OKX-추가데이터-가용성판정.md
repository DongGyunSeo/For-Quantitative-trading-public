# OKX API 추가 데이터 — 가용성 판정 (2026-08-20)

기존 5m OHLCV(2023-11~2026-07) 외에 OKX 에서 더 뽑을 수 있는 게 있는지 조사한 결과.

## 1. 경로/파라미터 해석 결과 (probe 2회차, 9/9 성공)

| 데이터셋 | 경로 | 비고 |
|---|---|---|
| funding_rate_history | `/api/v5/public/funding-rate-history` | ✅ 전 구간 |
| open_interest_history | `/api/v5/rubik/stat/contracts/open-interest-history` | 페이지네이션 문제 있었음 (§2) |
| taker_volume | `/api/v5/rubik/stat/taker-volume-contract` <br> 또는 `/api/v5/rubik/stat/taker-volume` + `instType=CONTRACTS` | 두 경로 모두 해석됨 |
| long_short_ratio | rubik | |
| liquidation_orders | `+{instType:SWAP, uly:BTC-USDT, state:filled}` | 응답이 중첩 `details` 배열 → 평탄화 필요 |

문서에 없거나 문서와 다른 조합이 다수라 **경로 × 파라미터 행렬 탐색**(`OKXClient.resolve()`)으로 자동 해석하도록 구현.

## 2. 페이지네이션 오탐 (v0.17.0 에서 수정)

증상: `✓ oi BTC 97행 2026-08-19 ~ 2026-08-20 [after, 3p, 페이지 소진]`
— 3페이지를 받았는데 8시간치뿐.

원인: rubik 계열은 `after` 커서를 **무시하고 같은 최신 창을 그대로 반환**한다.
기존 스타일 탐지기는 "응답이 비어있지 않으면 그 스타일이 동작한다"고 판정 →
같은 창을 3번 받고 "페이지 소진"으로 종료.

수정: 스타일 채택 조건을 **엄격한 전진**으로 변경.

```python
older = int(probe[spec.ts_col].astype("int64").min())
if older >= cursor:      # ★ 비어있지 않다는 것만으로는 부족
    continue
```

회귀 테스트 `test_style_detection_rejects_non_advancing_page` 추가
(`after` 를 무시하고 `begin`/`end` 만 존중하는 mock 서버 → `style == "begin_end"` 로
판정되고 250행 전부 회수되는지 검증). 테스트 145 → 146.

## 3. 보존 기간 — 핵심 제약

2회차 probe 에서 관측된 사실:

- `taker_volume`: `limit=100` 을 무시하고 **576행(≈2일)** 반환
- `long_short_ratio`: 동일
- `open_interest_history`: `limit=100` 을 존중

→ **rubik 5m 통계의 보존 한계는 약 2일**로 추정된다.
우리가 필요한 구간은 2023-11 ~ 2026-07 이므로

> **5m rubik 통계(taker/LSR/OI)는 소급 백테스트에 쓸 수 없다.**
> 실시간 기록용(forward recording)으로만 가치가 있다.

1H/1D 보존 기간은 아직 미측정 → `--retention` 이 이걸 측정한다.

## 4. 다음 진단 (사용자 로컬 실행 필요)

```
python examples/okx_fetch.py --retention   # period {5m,1H,1D} × limit {100,1000} 실제 깊이
python examples/okx_fetch.py --liq         # 청산 주문 details 평탄화 + 실제 커버 구간
```

`--retention` 결과가 결정하는 것:
**OI 기반 캐스케이드 탐지가 소급 가능한가, 아니면 전방 기록만 가능한가.**
소급 불가면 청산 히트맵(가격/거래량 기반 추정)을 계속 쓰는 수밖에 없다.

## 5. 펀딩 — 이미 확정된 결론

펀딩은 전 구간 확보 가능하고 이미 전략 손익에 반영했다.
부호 규약: `fundingRate > 0` → 롱이 숏에게 지급 → **숏이 수취**.

```
funding_R = −(포지션 부호) × rate_bps / risk_bps
```

미결 항목: **TRX 제외 재집계**. TRX 펀딩은 −1.138bps(양수 비율 32%)로
후보 엣지의 약 23% 를 잠식하며, 앞선 여러 검증에서도 일관되게 최하위였다.
