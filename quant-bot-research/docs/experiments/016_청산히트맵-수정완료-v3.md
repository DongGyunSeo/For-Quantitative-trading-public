# 청산 히트맵 v3 — 버그 수정 완료 및 재검증 (2026-08-20)

[`청산히트맵-설계검증.md`](015_청산히트맵-설계검증.md) 에서 찾은 결함을 전부 수정하고 재측정했다.

**가장 중요한 결과: 수정하고 나니 `liq_imbalance_hm` 의 자석 신호가 사라졌다.
v2 의 +2.28%p 는 신호가 아니라 버그 그 자체였다.**
반면 `sweep_liq_consumed` 는 800/800 완전 동일 — **기존 전략 결과는 전부 유효하다.**

## 수정 목록

| # | 항목 | 조치 |
|---|---|---|
| 1 | **시간 순서 무시 소멸** | `_build_heatmap` 재작성. 풀은 자신이 생성된 **이후** 통과에만 소멸 |
| 2 | LOOKBACK 문서/코드 불일치 | 문서를 코드값(288 = 24h)에 맞춤 |
| 3 | MMR 구조 반전 | `_safe_leverages()` 로 `MMR >= 1/L` 퇴화 버킷 제외 + 모듈 로드 시 검증 |
| 4 | `direction` 대소문자 취약 | `"LONG"` 도 정상 처리 |
| 5 | 성능/불필요 계산 | `skip_decay=True` 추가 — 소진량만 필요한 경로에서 소멸 계산 생략 |
| 6 | 미검증 피처 경고 | `pool_net_draw` 사용 전 검증 필요를 docstring 에 명시 |
| 7 | 8중 계상·저레버리지 무효 | 한계로 docstring 에 명시 |
| 8 | 감사 스크립트 NaN 버그 | `heatmap_audit.py` 의 볼륨프로파일 상관 계산 마스크 수정 |

### 1번 수정의 수식

```
heat[b] = Σ_j  w_j(b) · exp( L(b,N) − L(b,j) )
L(b,k)  = Σ_{i<=k, 봉 i 가 bin b 통과} log(1 − consume_rate_i)
```

`exp(L(b,N) − L(b,j))` = 봉 j **이후** 의 생존율. v2 는 `exp(L(b,N))` 을 모든 풀에
일괄 적용했다. 구현은 (n_bars × bins) diff 배열에 bin 방향 → 시간 방향 두 번 cumsum.

**검증 (수치 재현)**

| 시나리오 | v2 survive | v3 survive | 기대 |
|---|---|---|---|
| 통과 → **이후** 풀 생성 | 1.0e-06 | **1.0000** | ≈1 |
| 풀 생성 → **이후** 통과 | ~0 | **<0.01** | ≈0 |

두 케이스 모두 `tests/test_liqheatmap.py` 에 회귀 테스트로 고정 (총 10개).

## 영향 ① 전략 결과 — 불변 확인

BTC 800개 무작위 시점에서 `sweep_liq_consumed` 를 v2 / v3 비교:

```
동일: 800/800  (불일치 0건)
```

소진량은 `heat_raw`(소멸 전)만 쓰므로 당연한 결과지만, 이걸 못 박아야
이전 검증 문서 전부가 유효하다고 말할 수 있다. 회귀 테스트로도 고정했다.

**속도도 개선**: 이벤트 탐지 경로에 `skip_decay=True` 를 적용해
0.81ms → **0.59ms/call** (27% 단축). 전체 소멸 계산은 1.49ms.

## 영향 ② imbalance — 신호가 아니라 버그였다

v2 와 v3 의 `liq_imbalance_hm` **부호 일치율 51.5%** (사실상 무관한 두 피처).
크기 중앙값도 0.285 → 0.108 로 축소.

동일 표본(4심볼 × 2,500)에서 자석 가설 재측정:

| 배리어 | v2 | **v3 (수정 후)** |
|---|---|---|
| ±4 ATR | 49.65% (p=0.50) | 50.79% (p=0.12) |
| ±12 ATR | 51.15% (p=0.023) | 50.70% (p=0.17) |
| **±36 ATR** | **52.28% (p=0.0003)** | **48.54% (p=0.020)** |
| ±36 ATR, \|imb\|≥0.3 | 54.62% (p=0.0001) | **40.65% (p=0.0075, n=214)** |

심볼별 (v3, ±36ATR): BTC 48.6 / DOGE 44.3 / ETH 49.8 / TRX 50.9 — **0/4 가 51% 미만.**

### 왜 v2 가 맞아 보였나

v2 는 가격이 최근 지나간 모든 bin 의 풀을 (생성 시점 무관하게) 전멸시켰다.
그래서 살아남은 풀은 **가격이 최근 지나가지 않은 영역** 에 몰렸고,
imbalance 는 사실상 "최근 레인지 안에서 어느 쪽에 미답 공간이 더 많은가"
= **레인지 내 위치 지표** 를 측정하고 있었다. 청산 유동성과는 무관하다.

수정으로 그 대리변수가 제거되자 예측력이 사라졌다.
(±36ATR 에서 48.5% 로 유의하게 음수지만 t≈-2.3, 심볼 일관성도 없어 신호로 보지 않는다.)

## 최종 피처 처분

| 피처 | 상태 | 판단 |
|---|---|---|
| `sweep_liq_consumed` | 수정 무관, 값 동일 | **유지 가능.** 단 전략 기여는 상위 1% 극단 랭킹 외엔 0. 더 단순한 지표(레인지×거래량)로 대체 시험 권장 |
| `liq_imbalance_hm` | **v2 신호는 버그 artifact** | **사용 금지.** 직전 문서에서 "유일하게 살릴 가치" 라 한 판단을 철회한다 |
| `pool_net_draw` | 동일하게 `heat` 기반 → 같은 오염 | **사용 금지.** 단변량 검증도 여전히 없음 |

## 남은 한계 (수정 불가, OHLCV 근사의 상한)

- 거래량 = 신규 진입 가정 (청산·손절·차익실현 포함 과대계상)
- 매 거래 롱·숏 × 4레버리지 = **8중 계상**, OI 넷팅 없음 → 절대량 무의미
- 적응 범위가 좁으면(±1.5%) 10x 버킷(±9.5%)은 범위 밖 → 실질 50x/100x 지배
- 소멸률 계수 `0.5` 는 여전히 근거 없는 임의값 (이제 `heat` 만 영향)

근본 검증은 CoinGlass 히트맵 / OKX 청산 피드와의 상관 측정뿐이다.
