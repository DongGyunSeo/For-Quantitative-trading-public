# 청산 히트맵 모듈 설계 검증 (2026-08-20)

`liquidation_heatmap_features.py` 자체를 감사했다. 실증 4종(상수 민감도 / 실체 /
시간순서 / 예측력) + 코드 정독. 재현: `examples/heatmap_audit.py` (4심볼 × 2,000~2,500표본).

**요약: 구조 결함 2개(시간순서 무시, MMR 반전), 문서-코드 불일치 1개.
상수 대부분은 순위에 무해하지만 그만큼 '청산' 특유의 정보도 얇다.
`liq_imbalance_hm` 은 큰 스케일에서 약하지만 실재하는 자석 신호(+2%p)를 가진다.
`sweep_liq_consumed` 는 소멸 처리와 무관한 값이며(raw 풀만 사용), 전략 기여는 0이었다.**

## 1. 상수별 타당성 판정

| 상수 | 값 | 판정 | 근거 |
|---|---|---|---|
| `LOOKBACK_BARS` | **문서 4032 / 코드 288** | ⚠ 불일치 | 모듈 헤더는 14일, 실제는 24h. 어느 쪽이 의도인지 확정 필요. 순위 영향은 작음 (4032 로 바꿔도 ρ=0.94) |
| `LEVERAGES=(10,25,50,100)` | | △ 사실상 (50,100) | SL 적응 범위가 ±1.5~10% 라 10x 청산가(±9.5%)는 거의 범위 밖. (50,100)만 써도 ρ=0.97. 저레버리지(5,10)로 바꾸면 표본의 94%가 계산 불능 |
| `MMR=0.005` | | ⚠ **구조 취약** | 롱 청산가 = (1−1/L+MMR)e 이므로 **MMR ≥ 1/L 이면 청산가가 진입가 위로 반전**. L=100 은 MMR 1%에서, L=50 은 2%에서 반전. 실제 OKX 고레버리지 티어 유지증거금 0.4~1% → 100x 버킷은 경계선 위. MMR 을 0.02 로 바꾸면 순위 ρ=0.83 까지 흔들림 — **이 상수는 load-bearing 인데 근거가 없다** |
| `N_PRICE_BINS=240` | | ○ | 40개로 줄여도 ρ=0.92. 둔감 |
| `ADAPT_RANGE_MULT=2.5` | | ○ | 1.0/5.0 으로 바꿔도 ρ≈0.999. 사실상 무의미한 파라미터 (consumed 가 비율이라 범위에 둔감) |
| 소멸률 `0.5×(vol/avg)`, cap `0.999` | | ⚠ 임의 + 과격 | 평균의 2배 거래량 봉 하나가 통과 구간 풀의 99.9%를 지움. 근거 없는 계수. 단 **`sweep_liq_consumed` 에는 아예 영향 없음** (raw 풀만 사용) — 소멸 상수는 imbalance/net_draw 에만 작용 |
| `IMB_ATR_MULT=100, C=3, inv2` | | △ | "11/11 격자검증 채택" = **인샘플 그리드 서치**. 아래 D 테스트에서 신호 자체는 확인되나 이 특정 값의 근거는 과적합 위험 |
| `pool_net_draw` 임계 0.02 | | △ | 임의. 해당 피처는 단변량 검증 자체가 없음 (모듈 주석도 인정) |
| 가드 `entry<50`, `window<50` | | ○ | 무해 |

## 2. "실제 유동성인가" — 아니다, 그러나 단순 변동성도 아니다

heat_raw 의 수학적 실체: OHLC4 볼륨 프로파일을 8개 배율
(0.905, 0.965, 0.985, 0.995 / 1.095, 1.035, 1.015, 1.005)로 복제해 합친 것.

| consumed 와의 순위상관 | ρ |
|---|---|
| 순수 볼륨 프로파일 (배율 1.0, 청산 수학 제거) | **+0.52** |
| TR/ATR rank (봉 크기만) | +0.18 |

봉 크기와는 거의 독립(0.18)이고, 볼륨 프로파일과는 절반만 겹친다(0.52).
즉 레버리지 시프트가 **고유한 순위 변형을 만들기는 한다**. 문제는 그 변형의 가치다:

- 전략 실험 3회에서 소진량 상위 필터의 기여 = 0 ~ 음수 (상위 20% 컷)
- 상위 1% 극단에서만 유효했는데, 그건 "역대급 캐스케이드 식별"이지
  청산가 역산 수학이 맞아서인지 불분명

근본 한계 (모듈 주석도 일부 인정): ① 거래량 = 신규 진입 가정 — 청산·손절·차익실현이
전부 포함돼 과대계상 ② 매 거래가 롱·숏 양쪽 × 4 레버리지 = **8중 계상**, OI 넷팅 없음
③ 레버리지 분포를 모름 (v2 에서 1/L 가중마저 제거).
**OI 데이터 없이 OHLCV 만으로는 여기가 상한이다.**

## 3. 구조 결함 — 시간 순서 무시 (가장 중요)

소멸(survive)이 **풀 생성 시각과 무관하게** 창 전체의 통과 이력을 끝에서 일괄 곱한다.
따라서 **통과가 일어난 뒤에 생성된 풀도 그 통과에 의해 소멸된다.**

수치 재현 (통과 → 이후 풀 생성 → 가격 미복귀):

```
90.5 구간 풀: raw=23,700 → after=0.024   (survive = 1e-06)
올바른 값: survive ≈ 1  (풀 전체가 통과 이후 생성)
```

영향 범위: `sweep_liq_consumed` 는 무관(raw 사용), **`liq_imbalance_hm` 과
`pool_net_draw` 는 직접 오염**. 특히 변동성 구간(청산 이벤트 직후!)에서
"최근 새로 쌓인 풀"을 과거 통과가 지워버리므로, 이 모듈이 쓰이는 바로 그 국면에서 왜곡이 최대.

수정 방향: 봉 순회하며 풀 누적과 소멸을 **동시 진행** (bin별 survive 를 시점별로 적용).
O(n×bins) 로 여전히 빠르다.

## 4. 예측력 — imbalance 자석 가설은 약하게 실재

무작위 1만 시점, `sign(liq_imbalance_hm)` 이 ±K·ATR 배리어 중 어느 쪽 먼저 닿는지:

| 배리어 | 적중률 | p | \|imb\|≥0.3 만 | 모멘텀 대조 |
|---|---|---|---|---|
| ±4 ATR | 50.47% | 0.36 | 50.88% | 50.32% |
| ±12 ATR | 51.16% | 0.023 | 52.15% | 49.61% |
| **±36 ATR** | **52.19%** | **0.0005** | **52.66%** | 50.89% |

- 방향: **자석(끌림)이 맞다** — 풀이 무거운 쪽으로 간다. 저항이 아니다.
- 스케일이 클수록 강해진다 (±36ATR ≈ ±5%). 단기 예측에는 무용, 큰 목표 방향 선택에는 +2%p.
- 모멘텀 대조군(50~51%)을 이긴다 — 단순 추세 재포장이 아님.
- 단, 시간순서 결함이 고쳐지면 이 수치가 오를 수도 있다 (지금은 오염된 상태의 성적).

## 5. 그 외 검증 필요 항목 (미완)

1. **`pool_net_draw`** — 단변량 검증 전무. imbalance 와 같은 방식의 first-passage
   테스트 필요 (소멸 결함 수정 후에).
2. **소멸률 계수 0.5** — imbalance 적중률을 목적함수로 {0.1, 0.25, 0.5} 비교 가능.
   단 인샘플 튜닝이 되지 않게 절반 데이터만 쓸 것.
3. **실데이터 대조** — CoinGlass 히트맵이나 OKX 청산 피드와 상관을 재보는 것이
   근본 검증. OHLCV 근사의 상한을 확인할 유일한 방법.
4. **거래소 티어별 MMR 반영** — 최소한 L=100 버킷의 반전 위험 제거
   (예: `assert mmr < 1/max(L)` 가드).

## 결론

- `sweep_liq_consumed` (이벤트 랭킹에 쓴 것): 상수엔 둔감, 소멸 결함과 무관.
  다만 전략 기여가 반복적으로 0 이었으므로 **유지 비용 대비 가치 낮음**.
  극단 캐스케이드 식별은 더 단순한 지표(레인지×거래량)로 대체 시험 가치 있음.
- `liq_imbalance_hm`: 결함(시간순서) 있는 상태에서도 +2%p 실신호.
  **수정 후 재측정할 가치가 있는 유일한 피처.**
- `pool_net_draw`: 검증 없이는 사용 금지.
- 우선 수정: ① 시간순서 소멸 ② LOOKBACK 문서/코드 통일 ③ MMR 가드.
